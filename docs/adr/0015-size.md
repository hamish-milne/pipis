# 15. Size claims are measured, and a gate holds them

**Decision.** `node packages/pipis/tools/size.ts` bundles small programs that use pipis the way an app would (Rolldown, minified, tree-shaken) and
measures them raw, gzip and brotli. `--check` fails if a scenario's gzip size is more than 2% and 16 bytes over `packages/pipis/tools/size-baseline.json`,
and it is part of `all`. Only numbers from this table are published.

**Measured** (gzip bytes):

| Scenario                                                | gzip  | brotli |
| ------------------------------------------------------- | ----: | -----: |
| A static element (core only)                            |   802 |    703 |
| The counter app (`reactive`, `select`, `createElement`) | 1,129 |  1,010 |
| Every export, in one program                            | 2,416 |  2,204 |

A feature costs this much on top of the counter app: `patch` +126, `If` +142, `OneOf` +164, `Dynamic` +154, `Effect` +65, `Watch` +89,
`List` +334, `ReactiveList` +358, `adapt` +68, `Suspense` +368, `ErrorBoundary` +227, `Portal` and `PortalTarget` +222, `Helmet` +73, and writing
the counter in JSX +18.

**Why.** A size claim that cannot be checked rots, and "under 1 KB" is true only for the core. A gate makes every claim a number that is
re-measured on each change.

**Consequences.** The README and the introduction quote this table. Changing the baseline is a deliberate commit that says why
(`RUNBOOKS.md`, "Change the size baseline"). The gate measures gzip only; brotli is shown for information.
