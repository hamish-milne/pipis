# 15. Size claims are measured, and a gate holds them

**Decision.** `node tools/size.ts` bundles small programs that use pipis the way an app would (Rolldown, minified, tree-shaken) and
measures them raw, gzip and brotli. `--check` fails if a scenario's gzip size is more than 2% and 16 bytes over `tools/size-baseline.json`,
and it is part of `all`. Only numbers from this table are published.

**Measured** (gzip bytes):

| Scenario                                                | gzip  | brotli |
| ------------------------------------------------------- | ----: | -----: |
| A static element (core only)                            |   784 |    685 |
| The counter app (`reactive`, `select`, `createElement`) | 1,118 |    987 |
| Every export, in one program                            | 2,412 |  2,204 |

A feature costs this much on top of the counter app: `patch` +140, `If` +139, `OneOf` +161, `Dynamic` +151, `Effect` +60, `Watch` +86,
`List` +331, `ReactiveList` +355, `adapt` +64, `Suspense` +365, `ErrorBoundary` +226, `Portal` and `PortalTarget` +221, `Helmet` +71, and writing
the counter in JSX +17.

**Why.** A size claim that cannot be checked rots, and "under 1 KB" is true only for the core. A gate makes every claim a number that is
re-measured on each change.

**Consequences.** The README and the introduction quote this table. Changing the baseline is a deliberate commit that says why
(`RUNBOOKS.md`, "Change the size baseline"). The gate measures gzip only; brotli is shown for information.
